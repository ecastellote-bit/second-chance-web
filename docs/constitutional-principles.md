# Second Chance — Constitutional Principles v1

## 1. Generalización radical
Second Chance no debe construirse para un caso humano excepcional ni para un perfil singular que “encaja” muy bien con el sistema.
Debe servir a cualquier adulto alfabetizado que pueda narrar su historia por escrito con claridad razonable.

## 2. No parche
No agregar reglas, motores, bloques, prompts o atajos ad hoc que no pertenezcan a la arquitectura final del producto.
Toda solución nueva debe poder defenderse como parte del sistema definitivo, aunque inicialmente exista en versión lite.

## 3. Arquitectura definitiva + profundidad parcial
El MVP no debe ser un juguete descartable.
Debe construirse con la columna vertebral del sistema final desde el comienzo, aunque varios módulos operen inicialmente con menor profundidad.

## 4. Honestidad diagnóstica
El sistema no debe inventar una dirección vocacional para completar el formato.
Debe preferir una lectura honesta e incompleta antes que una conclusión falsa pero elegante.

## 5. Honestidad intelectual contextual
Si un término, referencia, módulo, sigla o elemento no está claro, debe decirse explícitamente.
No fingir comprensión.
No rellenar lagunas con seguridad artificial.

## 6. Múltiples salidas válidas
El sistema debe poder concluir legítimamente en:
- clear_direction
- compressed_life
- insufficient_evidence

No toda historia debe terminar en una “vocación detectada”.

## 7. Distinción estructural
Second Chance debe diferenciar, sin colapsar categorías:
- rasgo
- herramienta
- arena
- función
- refugio
- vida comprimida
- dirección plausible

## 8. Transición realista
La utilidad del sistema no está en diagnosticar una esencia ideal, sino en reducir confusión y orientar movimientos plausibles dadas:
- la historia del usuario
- sus capacidades
- sus restricciones reales
- su margen de transición

## 9. Comunidad como capa estructural
El diagnóstico no es el final del producto.
La comunidad existe para contraste, validación humana, decantación y continuidad de transición.

## 10. Fricción útil
El producto no debe ser arbitrariamente difícil, pero tampoco vaciar profundidad para parecer liviano.
Debe conservar la fricción mínima necesaria para producir lectura seria.

## 11. Sobriedad expresiva
El sistema no debe sonar marketinero, mesiánico, infantil, naïf ni terapéutico.
Debe sonar serio, claro, humano y sobrio.

## 12. Utilidad humana real
El sistema debe ayudar al usuario a:
- entender mejor su patrón
- distinguir cansancio de dirección
- recibir 1 o 2 movimientos plausibles
- salir con una acción pequeña y realista

## 13. Re-entry estructural
El sistema debe permitir que el usuario:
- agregue información
- corrija respuestas
- matice su historia
- recalcule la lectura

## 14. No sobrepromesa
Second Chance no promete revelar una verdad total sobre una persona.
Promete una lectura mejor estructurada que un test convencional y un puente más serio entre confusión y movimiento posible.
